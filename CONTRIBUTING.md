# Как вносить изменения

## Ветки

- `main` — стабильная ветка. Всё, что в ней, автоматически публикуется на `https://<проект>.pages.dev`. Прямые коммиты в `main` запрещены правилами репозитория.
- Рабочие ветки — от `main`, по одной на задачу:
  - `feature/<кратко>` — новая возможность (`feature/library-legend`);
  - `fix/<кратко>` — исправление (`fix/spoiler-day-7`);
  - `content/<кратко>` — правки текстов и фактов (`content/severinus-dossier`);
  - `chore/<кратко>` — инфраструктура, зависимости (`chore/deps-2026-11`).

## Порядок работы

```bash
git switch main && git pull
git switch -c feature/my-change
# … правки …
npm run check            # линтер, типы, тесты, сборка, проверка сборки
git add -A && git commit -m "Карта: подписи башен библиотеки"
git push -u origin feature/my-change
```

Затем откройте pull request в `main`. Для него автоматически:

1. GitHub Actions запускает проверку **check** (без неё кнопка слияния заблокирована);
2. Cloudflare Pages собирает **предпросмотр** по адресу вида `https://feature-my-change.<проект>.pages.dev`.

Когда проверка зелёная и предпросмотр выглядит правильно — **Squash and merge**. Через 1–2 минуты изменения на основном адресе.

## Стиль кода

Проверяется автоматически: `npm run check` и CI не пропустят код, который не прошёл форматирование и линтер.

- **Форматирование** — Prettier (`.prettierrc.json`: ширина строки 120, одинарные кавычки). Перед коммитом: `npm run format`. CSS и `wrangler.jsonc` пока не форматируются: тесты вёрстки проверяют исходник стилей.
- **Импорты** — сортирует ESLint (`npm run lint -- --fix`): сначала пакеты, затем модули проекта по пути. Все импорты в начале файла, из одного модуля — один импорт.
- **Где что лежит:**
  - `data/` — только содержание и производные выборки, без React;
  - `lib/` — чистые функции и хуки без разметки;
  - `components/` — переиспользуемые компоненты, по папкам `ui/`, `cards/`, `map/`; один компонент (или маленькая группа однотипных, как чипы) на файл;
  - `sections/` — страницы сайта: собирают компоненты, свою логику держат минимальной.
- **Имена файлов** — компонент: `PascalCase.tsx` по имени компонента; хук: `useCamelCase.ts`; модуль функций: `camelCase.ts`.
- **Размер** — если файл компонента перевалил за ~300 строк, вынесите логику в хук, а части разметки — в отдельные компоненты.
- **Комментарии** — по-русски, объясняют «почему», а не пересказывают код.
- **Тексты интерфейса** — только по-русски (это проверяет `tests/localization.test.ts`).

## Сообщения коммитов

Коротко, по-русски, в повелительном или назывном виде, с разделом в начале: «Хронология: …», «Карта: …», «Данные: …», «CI: …».

## Откат

Cloudflare Pages хранит все развёртывания: Workers & Pages → проект → Deployments → нужное развёртывание → **Rollback to this deployment**. В репозитории — `git revert <коммит>` через обычный PR.
